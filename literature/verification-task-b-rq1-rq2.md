## Important corrections

- Seoane’s 8.6/9.5/10.2 ms MQTT results use the relocated same-VM publisher/subscriber scenario (p. 10), rather than the original Raspberry Pi publisher CPU/bandwidth arrangement (RQ1 F3).
- Babovic’s Silverlight/Flash socket results are not interchangeable with native HTML5 WebSocket (p. 6986; RQ1 F9).
- Pimentel’s 2.3–4.5× ratio holds for polling versus WebSocket; the Japanese long-polling rows can exceed polling (Table 1, p. 50; RQ1 F10).
- Silva’s local TTC prose gives 1051 ms whereas Table 7 gives 1015.28 ms (pp. 20–21). The source mentions lack of synchronization but omits an operational cross-device clock procedure (pp. 17/20); the earlier “no mention” assertion was too broad.
- Saif’s memory metric is total heap allocations, not RSS/live heap, and ps lifetime CPU averaging is not psutil’s interval averaging (Sec. VI-C, arXiv PDF 3–4; RQ2 F10).
- Paul’s 10K msg/s VM1 ceiling conflicts with its later 26K-to-40K comparison within Sec. V-B (arXiv PDF 7). Memory figures are supported, but throughput cannot be treated as a clean hardware ceiling (RQ2 F8).
- psutil’s previous quotes were not verbatim in the current inspected documentation. The stable 7.2.2 API entries support the claims after replacing quotes and qualifying cross-tool comparability.
- Ten repetitions are a literature precedent, not a validated sample-size minimum (RQ2 F14).

Other numerical values checked here are stated in text/tables, so no graph-only decimal estimates were used. Quotation comparison allowed layout line wraps, discretionary hyphens and typographic ligatures; these are not classified as invented text. Long multi-sentence resource quotations were reduced to short verbatim excerpts.
